BUILD PROMPT - PINK CLOUD CORRECTION EDITOR (page 2 of 3)
Paste everything below into your coding agent.
================================================================

You are building the correction editor page of Pink Cloud. Pink Cloud is an offline Tamil OCR web app: Vanilla JS, HTML, CSS. No frameworks. No build step. No CDNs. No internet calls at runtime.

Goal: one screen with the scan on the left, Unicode Tamil text in the middle and a review queue on the right. Clicking a word highlights its box on the scan. Doubtful words are easy to find, fix and accept.
Done when: the page loads schema/doc_demo.json offline, draws every line box on the scan, links clicks both ways, J jumps to the next doubt word, and the fix popup turns வாழறிவன் into வாலறிவன் on Accept, marks it "human" and shows a toast.

7. CLICK-TO-SYNC (one selection model for all panes)
----------------------------------------------------------------
- There is exactly one active word, or none.
- Word key: "p{page}:{lineId}:w{index}". index = the 1-based position of the word in its line.
- Click a word in the text pane: it becomes active. The scan shows the active box for the same key. If the box is outside the viewer, scroll the viewer so the box sits at 1/3 of its height (160ms). If the word is in the queue, mark that row active and scroll it into view.
- Click a box on the scan: the same result, mirrored. The text pane scrolls the word to 1/3 height.
- Click a queue row: the same as clicking the word. Both panes scroll.
- Hover a word or box: the hover style shows on both sides. Hover never scrolls and never changes the active word.
- Click on empty space: nothing changes.
- Esc: closes the popup first. A second Esc clears the active word.
- Page badge click: clear the active word and scroll all panes to the top.

----------------------------------------------------------------
8. HOTKEYS (ignored while focus is in a text input, except Enter/Esc inside the popup)
----------------------------------------------------------------
  J      next queue item after the active one. At the end of a page, go to the first item on the next page. At the very end, toast "Queue done".
  K      previous queue item.
  Enter  open the fix popup on the active word. Inside the popup: Accept.
  Esc    inside the popup: Reject and close. Otherwise: clear the active word.

  quality: blur, contrast, noise, skew_deg (required); damage_flags[], ink_density, estimated_lines, quality_score (optional).
  lines[]: { id "L1", seq (1-based reading order), body (Tamil text), bbox [x,y,w,h] in px on the 1600px image, confidence 0-1, kural? }
  text: the corrected line bodies stitched in seq order.
  Optional: preprocessed (bool), needs_review (bool), words[] { text, bbox, confidence }, corrections[] { before, after, tier, evidence }, verdicts[], processing_ms, work, chapter, script, material, specimen, manuscript_id, license, doi.
Mock: schema/doc_demo.json has page 1, profile HEAVY, preprocessed true, needs_review true, and 3 lines:

  corrections: [{ before "வாழறிவன்", after "வாலறிவன்", tier "T1", evidence "ழ/ல glyph confusion ..." }]
Rules for rendering:
- Words: if words[] is present, use it. Assign each word to the line whose bbox contains the word's bbox center. Otherwise split lines[].body on spaces. Give each word the line's confidence, and a box made by splitting the line bbox in proportion to character count. Label these boxes as approximate in code.
- Confidence bin = the word's confidence, or its line's confidence.
- Provenance: default raw. A word equal to a corrections[].before (the OCR text) is a correction target: show "before" on the scan tooltip and "after" as the suggestion in the popup. Tier map (confirm with the team): T1 = swap, T2 = rule, T3 = llm. After Accept, the word becomes human.
- The page badge state comes from profile + preprocessed + needs_review: FAST and not needs_review = Clean; HEAVY with preprocessed = Repaired.
- Do not add fields to the contract. If you need one, stop and ask. Only new optional fields are allowed, added to schema and mock in the same commit.
