--------------------------------------------------
DESIGN PHILOSOPHY
--------------------------------------------------

The UI will be used by a broad audience, primarily Indian users including Tamil-speaking users.

Follow these UX principles:

1. Hick's Law
   Reduce unnecessary choices and visual complexity.
   Do not turn the page into a rainbow of colors.

2. Jakob's Law
   Use familiar semantic conventions:
   - Green = success / accepted
   - Amber = warning / requires attention
   - Red = error / destructive
   - Blue = information / focus
   - Neutral gray = system/default/raw

3. Von Restorff Effect
   Orange is the product's distinctive accent.
   It should stand out because it is used selectively, not everywhere.

4. Aesthetic-Usability Effect
   Keep the interface calm, professional, spacious and visually refined.

5. Accessibility
   Maintain strong readable contrast, especially on mobile.
   Avoid pure #000000 and pure #FFFFFF.
   Color must not be the ONLY way information is communicated.

The visual direction is:

+
CHARCOAL TYPOGRAPHY
+
ORANGE BRAND ACCENT
+
CONVENTIONAL SEMANTIC COLORS

Do NOT introduce purple.

Do NOT automatically make blue the primary brand color.

--------------------------------------------------
IMPORTANT TOKEN ARCHITECTURE
--------------------------------------------------

Do not treat every token as an unrelated color.

Reuse semantic meaning wherever possible.

For example:

--color-confidence-ok
and
--color-success

may resolve to the same primitive color.

Likewise:

--color-confidence-doubt
and
--color-warning

may share the same primitive.

Create the CSS so the architecture resembles a professional token system.

Ideally structure it conceptually as:

1. Primitive / foundation colors
2. Semantic tokens
3. Component tokens

For example:

--orange-600: #F25A1A;
--orange-700: #D94A0F;

--color-brand-primary: var(--orange-600);

--button-primary-bg: var(--color-brand-primary);

Do this cleanly without creating hundreds of unnecessary variables.

--------------------------------------------------
BRAND COLOR RULE
--------------------------------------------------

Orange is NOT a semantic warning color.

Brand orange and warning amber must remain visually distinguishable.

Orange should primarily represent:

- primary actions
- active scanning
- active product emphasis
- brand recognition
- selected high-priority actions

Warning amber represents:

- uncertainty
- caution
- something requiring review

--------------------------------------------------
VON RESTORFF RULE
--------------------------------------------------

Because orange is the most distinctive color in the system, protect it.

Do not put orange on:

- every icon
- every heading
- every selected item
- decorative backgrounds
- every card

The page should be approximately 80–90% neutral.

Orange should feel intentional when it appears.

--------------------------------------------------
ACCESSIBILITY
--------------------------------------------------

The documentation should demonstrate accessibility-aware usage.

Important:

Do not reduce text contrast simply to make the interface look softer.

Instead achieve softness through:

- off-white backgrounds
- charcoal rather than pure black
- muted borders
- restrained saturation
- whitespace

Normal body text must remain clearly legible.

Use visible :focus-visible styles.

Do not use color as the sole indication of state.
